Supply chain, GitOps, JFrog, Argo CD

Block the release before a fixable vulnerability or a brand-new package ships.

A policy gate for SBOMs and scan reports, a SonarQube check, flag rollout guardrails, JFrog promotion, and GitOps overlays where production only ever pins an image digest.

Every gate fails closed and says why.

Each check is plain code you can read, test, and run in any pipeline.

Release gate

Reads a CycloneDX SBOM and a scan report. Blocks fixable high and critical findings, denied licenses, unpinned components, and versions published in the last 7 days.

gate/policy.py

SonarQube gate

Fails the build unless the project quality gate is OK, and prints the failed conditions.

gate/sonar.py

Flag guardrails

Checks a rollout plan: owner, kill switch, staging first, production starts at 1 or 5 percent and never goes backwards.

flags/validate.py

JFrog

An Xray policy that blocks fixable high findings, and a script that scans a build and then promotes it.

jfrog/, scripts/promote.sh

GitOps with Argo CD

Kustomize base with dev and prod overlays. Dev syncs itself, prod waits for a person. Prod pins an image digest, never a tag.

gitops/

Pipelines on three platforms

Azure DevOps, Harness with an approval stage, and GitHub Actions.

ci/, .github/workflows

Questions before you try it.

Why block versions published in the last 7 days?

Malicious or broken releases are usually caught within days. A short age floor is the same idea as JFrog Curation at the proxy. An allow list covers the exceptions.

Why is prod pinned to a digest?

A tag can be re-pushed. A digest cannot, so what Argo CD deploys is exactly what was scanned and signed.

Does this replace Xray or SonarQube?

No. It reads their output and decides. The gate logic is small on purpose so it is easy to review.
